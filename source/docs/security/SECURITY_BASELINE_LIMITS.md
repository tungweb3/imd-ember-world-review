# Proposed security baseline limits — R8 v1.1

Status: local repair candidate, 2026-10-04. This is a proposed limits register. It does not establish `WORLD_SECURITY_BASELINE_v1`, represent an external Swarm verdict, or assert that this candidate is deployed. The original finding reference is public snapshot `c4f451b015abdaced6c35a717b29f5bb1cb351c0`; this patch is based on the subsequently deployed local source parent `f9a34cba0876306287b35aff0176e9dc38942624`.

| Boundary / residual | What remains true and what is not established |
|---|---|
| Independent click intents | Every valid click obtains its own canonical session read. A GET is not an atomic cross-tab lock: two independent clicks can both read ABSENT. Signature/session guarantees are per valid click and nonce, not a global exactly-once promise across users/tabs. |
| BroadcastChannel | A local accepted transition may emit at most one hint; delivery can be lost. Receivers must reread, and the next explicit click must preflight even without a hint. |
| Late browser cookie headers | An already authorized cleanup can clear a later browser cookie when its headers arrive late. It must not revoke that newer session row. The cookie transport race remains documented; addresses and expiries do not identify a unique session credential. |
| Detached cleanup / browser termination | Old operation responsibilities survive a UI lifetime in memory. Offline failure, process death, tab destruction and delivery loss remain best effort. Expiry and server token/nonce checks remain authoritative. |
| Auth transport deadline | No bounded Auth fetch deadline is introduced. A stalled read can delay a click; restart does not wait indefinitely for an old cleanup before starting its own canonical read. |
| Clock model | Scoped cache freshness requires finite nonnegative age strictly below TTL. Epoch-based remote timestamps are never mixed with a local monotonic counter. Real regional clock skew and OS/provider time behavior are not exhaustively measured. |
| Ownership staleness | An authenticated ownerOf proof may be reused until its original 30-second deadline. A transfer immediately after the proof is discovered on the next due proof. Roster/index/name/public IDs never grant household authority. |
| Ownership cache and availability | Successful epochs bound attempted IDs to 256 per address and deduplicate positive, negative and failed delta attempts. This is per isolate and finite epoch, not a global RPC ceiling. First/expired proof failures have no valid epoch; existing authenticated home/chain/index lane limiters govern their retries. Multiple legitimate session credentials, colos, cache eviction or restarts can increase calls. A failed delta waits for the original epoch deadline before retrying the new IDs. |
| Market display | Parsed future floor retrieval times remain future and are hidden by the UI. Missing/unparseable upstream retrieval time uses the initial observation time. Failed cached merges cannot re-date existing data. Optional invalid derived numbers are absent; a valid finite negative price change remains valid. |
| Independent evaluator scope | Real AuthClient, Worker handlers, migrations and SQLite are executed. Timers, provider, visibility and transport are injected; each Worker/SQL route execution is a scheduler step. The bounded causal traces do not enumerate all D1 internal interleavings or actual OS/browser/wallet behavior. |
| Production environment | This candidate's Worker version, traffic assignment, Cloudflare bindings, WAF/limiter settings and deployed artifact parity require a separate deployment readback. Local tests cannot establish them. |
| Prior review limits | R4-03 smart-wallet write usability, R4-09 shared-network availability, AUD3-05 display residual and AUD3-09 review limit retain their prior documented scope. This patch does not recast them as fixed or as proof of fund safety. |
| Maintenance scan | The read-only cleanup provider retains existing historical-document duplication and long-file FAIL/REVIEW findings. Its Python dependency analysis does not parse this project's JavaScript/TypeScript and remains NOT_CHECKED. Source updates remain manual; no secure automatic updater was introduced. |

Use targeted retesting for a new boundary blocker. A visual/copy/music change still needs the relevant boundary check and smoke test; a change to Wallet/Auth/Session/Ownership/Contract/Mint/economy authority requires an appropriate new security review. External completion, Low/Info labels and passing tests are not certification, approval or zero-vulnerability evidence.
